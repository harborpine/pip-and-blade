# Decisions

The big design and technical calls, newest last. Each has a short reason.

## Foundation (10 Oct 2026)

1. **Use the Node.js already on this PC (v24.21), without changing system settings.** It is
   installed in the user profile but not on PATH. Every npm script calls its tools through
   `node` directly, so nothing depends on PATH or on Windows command shims (the folder name
   `Pip & Blade` contains `&`, which breaks some shims).
2. **The project lives in a OneDrive folder.** OneDrive will try to sync `node_modules`
   (tens of thousands of small files). It is harmless but noisy and can briefly lock files.
   If it causes errors the fix is to pause OneDrive sync or move the folder; noted in README.
3. **Rendering: plain DOM + CSS, with pixel-art PNG sprites.** No game engine. CSS transforms
   give 60fps slides/hops/shakes with no animation loop running while idle (battery).
4. **Engine is a pure reducer**: `apply(game, action) -> { game, events }`, JSON state,
   hash-based seeded randomness with separate streams per concern. This is what makes exact
   mid-fight resume, identical daily runs and fast headless simulation all fall out for free.
5. **Content is typed TypeScript data** in `src/content/` (not JSON): same "numbers live in
   data files" outcome, plus the compiler catches bad references.
6. **Items, enemy passives and difficulty tiers share one small trigger/effect language**
   (`src/shared/content.ts`), so a new rule-bending item is usually data only.
7. **The lead fixed the whole roster up front** (8 heroes, 25 enemies, 3 bosses, 40 items:
   ids, names and art briefs in `src/shared/roster.ts`) so art could start before the
   designer joined. The designer owns all numbers and behaviour.
8. **Rerolls are final; undo covers dice use only.** Undoing a reroll would let the player
   peek at outcomes. Undo walks back each die use to the moment rolling ended.
9. **Reckless cannot take a hero below 1 HP.** Keeps "no unavoidable deaths" honest and makes
   the low-HP build a real, readable strategy.
10. **Enemy turns contain no randomness.** Targets and amounts are fixed when the intent is
    shown, so the damage forecast on the End Turn button is exact.
11. **Gold exists only inside a run** (for shops). Nothing is carried between runs except
    feats, unlocks, tiers and records, so there is no grind currency.
12. **Sprites are individual PNG files** generated by `npm run art` and committed, listed in a
    manifest. Simple to review in the gallery, cached offline by the service worker.
13. **Service worker is generated by vite-plugin-pwa (Workbox)** precaching the entire build,
    so the game is fully offline after first load. The web manifest is a static file.
14. **Daily run uses all 8 heroes and the full item pool regardless of unlocks**, so the day's
    run is identical for a fresh profile and a veteran one.
15. **Tests run in Playwright's WebKit** (Safari's engine) at iPhone 14 size against the real
    production build served locally.

## Engine rule interpretations (accepted by the lead, 10 Oct 2026)

The engine teammate listed 24 places where the design left room. All were accepted as built.
The ones a player could notice:

16. Shield is not stripped on turn 1, so "start the fight with shield" items work.
17. An enemy drops its old shield just before it acts, so starting shield lasts one player turn.
18. Thorns answer every hit, even one that deals 0. Poison, Venom and Reckless never trigger thorns.
19. A second (Twin) hit on a target the first hit killed is lost.
20. A free single reroll (Pip Magnet) does not count as a reroll spent, so Poised still applies.
21. Daily runs record daily results, feats and collection, but not win streak or tier unlocks.
22. Abandoning a run counts as a loss.
23. A save that refers to content that no longer exists keeps all progress and drops only the run in progress.
24. After the Act 3 boss there is no reward screen: straight to victory.

## Balance and polish (10 Oct 2026)

25. **"Fury" anti-stall rule.** The robot players found fights that could never end. From
    turn 12 of a fight every enemy gains 1 Strength each enemy turn. It is one global rule
    (`Rules.fury`), shown to the player as a badge one turn ahead, and the damage forecast
    includes it.
26. **Extra balance check added by the lead: no trio of heroes may win more than 40%.** The
    first balance pass met every target but one party won 42%. The check was added (a
    stricter test, not a looser one) and the content retuned until it passed.
27. **Some items are weaker than their first one-line descriptions**, because the first
    versions broke the difficulty targets: First-Pick Glove multiplies by 1.5 (doubling gave
    a 55% win rate), Battle Drum and Last Word give +1.
28. **Feat wording: "win a fight with a living hero at exactly 1 HP"** rather than a whole
    run, which was too rare to be a fair unlock.
29. **Enemy numbers are scaled per act by dials in `src/content/tuning.ts`**, so difficulty
    can be nudged in one place.
30. **A "Use dice" button exists, but the game also switches to using dice by itself** when
    no reroll is possible, so the normal flow is roll, lock, reroll, tap die, tap target.
31. **The service worker is registered by the app's own code** (with error handling), not by
    an injected script, after the tester found the injected one could log an error.
32. **The phone tests replay one pinned winning game by real taps** (`tests/e2e/pinned.ts`).
    It must be re-pinned whenever balance numbers change; the test says so when it fails.
33. **Known limitation accepted:** on the smallest iPhones (375x667) boss fights draw the
    characters small, because the boss's spelled-out intentions take the room. Readable and
    fully tappable, but not as roomy as on a current iPhone.
34. **The phone tests use their own private local address (port 47613).** Another project on
    this PC uses the usual one, and its test runs stopped this project's test server halfway
    through a run. The game itself was not at fault.
